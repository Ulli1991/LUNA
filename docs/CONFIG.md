# Config reference

The 242 fields of `Config` (`src/luna/template_config.py`) and each test problem's own parameters (`cfg.problem`, the `Params` of its IC module). Set them in a config file or a run script with `dataclasses.replace`, or on the command line as `field=value` and `problem.<name>=value`. The tables are generated by `scripts/gen_config_md.py`; the notes at the end are written by hand.

## Notes

A `Config` is frozen: it is built once and changed only with `dataclasses.replace`,
so the object a run records in `run.json` is the object it ran with. Fields that
are 0 or `None` by default and are named below mean "derive it" (from the grid,
another field, or the problem), not literally zero.

### Problem and grid

- `test_problem` picks the initial condition from `luna/ic_generation/ic.py`;
  `problem` holds that IC's own numbers (its module's `Params`). Leave it `None`
  for the defaults. Changing `test_problem` swaps an untouched default `Params`;
  a changed one belonging to another problem is refused.
- On the command line a parameter is `problem.<name>=value`
  (`python main.py run.py problem.amp=0.01`); in a config file or run script it is
  `problem=jeans3d.Params(amp=0.01)` (`from luna.ic_generation import jeans3d`).
- `seed` seeds the random draws of a run: the turbulent cloud's velocity field and
  the coupled (Torch) star formation, which uses `seed + 7919`.
- `BOUNDARY` 1 (zero-gradient) lets gas flow in under an inward pull; isolated
  self-gravitating problems want 4 (diode: gas can leave, nothing enters).
  `BOUNDARY=3` is refused: isolated is a gravity boundary (`POISSON_BOUNDARY=3`).
- `units` defaults to dimensionless (every base unit 0). Physical runs attach a
  `UnitSystem`; cooling, chemistry, CC85, M82, Boss-Bodenheimer and the cloud need one.
- `ic_dir` reads the IC written once by `tools/write_ic.py`: each rank reads its
  own cells, and a directory written for another config is refused. Needed for
  the cloud at 1024^3.

### Hydro scheme

- `CFL` is in RAMSES form: dt = CFL / max over cells of sum_d (|v_d| + c) / dx_d
  (docs/HYDRO_TIMESTEP.md). The unsplit step is stable up to 1.
- `LIMITER` is used only with `ORDER=1`. `limiter_tangent_eps > 0` gives minmod a
  smooth tangent for autodiff (forward stays exact minmod); it needs
  `autodiff_mode`, `LIMITER=0` and no AMR (docs/AUTODIFF.md).
- `riemann_solver='hll'`: two-wave HLL (no contact), 1D-3D, the same normal-frame core layout as HLLC.
- `hydro_kernel='xla'` (default) is the XLA step; `'pallas'` (or `'auto'` on a GPU) is the
  Pallas MUSCL-Hancock kernel (1-D/2-D/3-D, any LIMITER, HLLC or HLL, FP64, FP32, recon32 in 3-D;
  bitwise the XLA step on a GPU), needed for chemistry's passive scalars. `'pallas'` refuses what
  it cannot run (autodiff_mode, ORDER=0, hydro_fused, recon32 outside 3-D, BOUNDARY=4 in 1-D/2-D,
  AMR, HLL with scalars); `'auto'` takes XLA there. On an A100 the 3-D step is 1.2-1.7x XLA, 1-D/2-D
  FP64 0.8-1.05x, FP32 1.3-1.6x (docs/HYDRO_KERNEL_PATHS.md); only Pallas fits 512^3 FP64 in 40 GB.
  `hydro_fused` is an alternative 3-D step, bitwise equal to the default; `hydro_recon32` reconstructs in FP32 with FP64 fluxes and state (3-D).
- `boundary_mass_budget` accumulates the gas mass in and out through each face
  (`state.sources["boundary_mass"]`, shape (2, 6); 3-D, BOUNDARY 0/1/4, not checkpointed).

### Time, output, restart

- `max_steps > 0` stops the loop after that many steps whatever `t_end` says
  (bounded benchmark runs). `enable_x64` is read by `main` before any array exists.
- `write_snapshots=False` turns off all snapshot I/O; `clear_output_dir=True` wipes
  `output_dir` first (validation runs, so stale snapshots are never stitched in).
- `enable_diagnostics` runs a device-side reduction every `diag_interval` steps; the
  NaN guard checks every step and, on a NaN, writes a checkpoint and raises.
- `timing_every=N` runs every N-th step part by part, with a table per part and a
  record in `<output_dir>/step_timing.jsonl` (docs/RUNNING.md).
- `restart_file=None` restarts from the newest checkpoint; `checkpoint_dir=None` is
  `<output_dir>/checkpoints`. `checkpoint_wall_time_interval` is in seconds (0: none);
  `max_checkpoints=0` keeps all.

### Devices and the kind of run

- `MESH_SHAPE` is the device grid, one entry per dimension, product = device count;
  `None` picks one. `decomposition='auto'` derives the data layout from the problem
  (`luna/setup/mesh.py`). `dm_pdims` is the blocks layout's process grid.
- `run` is "gas", "dm" (particles from `music_ic_path`, no gas grid) or "gas+dm" (a
  coupled box from a MUSIC baryon IC). Comoving time, AMR and autodiff are separate
  switches; a combination no runner supports is refused by validate().

### Gravity and cosmology

- `gravity_warm_vcycles`/`dm_warm_vcycles` carry the potential between steps and run
  k V-cycles on it instead of a cold full multigrid; 0 restores the cold solve. The
  potential is not checkpointed, so the first step after a restart solves cold.
- `gravity_warm_tol` (default 1e-4, as RAMSES) replaces the fixed count by cycles until the
  rms residual is below tol times the rms source, at most `gravity_warm_max_cycles` (10);
  0 brings back the fixed cycles. `gravity_warm_extrapolate` seeds the solve with the
  potential extrapolated in time; `gravity_proper_mixed` runs the proper-time cycles in FP32
  on the FP64 residual. docs/GRAVITY.md has the measurements.
- `gravity_precision`: 'double' FP64 everywhere; 'mixed' FP64 particles and potential
  with an FP32 deposit and defect-correction V-cycle; 'single' FP32 throughout.
  `gravity_deposit_fixed` deposits in fixed point: bitwise reproducible under
  particle reordering and exact in mass (int32, int64 with 'double').
- `POISSON_N_LEVELS=None` coarsens until a side is below 4. `gravity_mg_ca='auto'`
  leaves the communication-avoiding smoother off (it lost on every mesh measured,
  docs/GRAVITY.md); '1' turns it on. `gravity_kernel` is the
  gas kick, plain or with the sinks' field (Pallas: bitwise equal to XLA, 3.2x at 256^3 FP64
  on an A100; autodiff takes XLA). `gravity_energy='flux'` (what 'auto' picks where it runs) couples
  gravity to the energy through the hydro step's face mass fluxes (Mullen, Hanawa & Gammie 2020), so
  E_kin + E_th + W is conserved to the solve's tolerance, no floor needed: 3-D PLM gas on a proper clock,
  XLA or Pallas hydro, with or without dark matter; no sinks, chemistry, SiL corrector, `cosmo_rho_floor`
  or cc85 wind (docs/GRAVITY.md).
- The cosmology fields are read only when `CosmologicalIntegration` (the pancake's
  amplitude is `problem.a_caustic`). Floors and ceilings are off at 0;
  `cosmo_rho_floor` is a fraction of the mean and the mass it adds comes from the
  neighbours; `cosmo_T_init=0` starts at the CMB temperature.
  `cosmo_checkpoint_every` checkpoints grid, particles, a and tau every N steps.
- `dm_softening=0` is the PM cell; `dm_eta` is the acceleration time-step factor;
  `dm_face_capacity_factor=0` sizes the exchange buffer from the block surface.

### Equation of state, cooling, chemistry

- `isothermal_cs2 > 0` resets the energy so p = isothermal_cs2 rho after each step.
  `barotropic_eos` resets p from T(rho) = T0 [1 + (rho/rho_AD)^(gamma-1)]; the two
  are exclusive.
- Cooling is an explicit sub-cycled step after the hydro (`cooling_n_sub` is a cap,
  each sub-step at most `cooling_dt_frac` of the local cooling time), with a floor at
  `cooling_T_floor`. `cooling_X_H` and `cooling_ne_per_nH` form n_H and n_e in the
  rate; validate() warns when `cooling_X_H` differs from `units.HYDROGEN_MASSFRAC`.
- `cooling_mu` is the mean molecular weight of the cooling rate, and also of the CC85
  and M82 ambient gas in their ICs.
- `chemistry='net5'` runs chemcool network 5 in every cell in place of the cooling
  stage (docs/CHEMISTRY.md); it needs `units`.

### Sources

- `ou_config` (None: off) is the Ornstein-Uhlenbeck forcing after each hydro step.
  `sil_weights` is a trained CNN flux correction (`tools/sil3d.py`; periodic 3-D).
- CC85: Mdot = eta_M SFR and Edot = eta_E (SFR / 100) 1e51 erg/yr inside
  `cc85_R_star_pc`. M82: a Miyamoto-Nagai stellar disk (`m82_stellar_MN_*`, masses
  in 1e10 Msun, lengths in kpc) plus an NFW halo; the M82-Disk-3D IC uses the same
  potential.
- Point masses (disc-planet, 2-D): a central star and a planet on a fixed circular
  orbit, Plummer-softened. The sink options drain gas near them; the damping zones
  relax the disc edges to the IC (de Val-Borro 2006).

### Radiation

- M1 is an operator-split stage with its own reduced speed of light `rad_chat`
  (required > 0); `rad_c_true=0` uses `rad_chat` for the force. The field is not
  written to checkpoints, so a restart with radiation on is refused.
- The `*_groups` tuples override the scalar per group; empty means the scalar in
  every group. `rad_cfl` is per sweep on dx/c_hat for `hancock_split`, on
  dx/(ndim c_hat) for `rk2`. `rad_closure='m2_entropy'` is a reference only
  (hours per step). `rad_remat` recomputes the step in the backward pass.
- `rad_ionization` makes the radiation state (photon field, ionized fraction) and
  prescribes P = rho cs^2(x) (STARBENCH); it is refused with cooling. Its numbers come
  from `luna.radiation.ionization.starbench_units`, in code units;
  `rad_source_radius=0` is 2 dx; `rad_neutral_eos_table` makes the neutral cs^2
  follow density (docs/WALL_M3.md).

### Sinks and coupled stars

- Sinks form above `sink_creation_density` (0: never), accrete inside
  `sink_accretion_radius` (0: 2 dx), are softened by `sink_softening` (0: 2 dx), and
  keep `sink_creation_separation` (0: 4 dx) apart; `sink_create_frac=0` is 0.9.
  'federrath' and 'flash' are FLASH-Torch's rules (docs/TORCH.md).
- `sink_sink_gravity` must be off when an N-body code (PeTar under Torch) owns
  star-star gravity, or it is counted twice.
- `sink_star_T_max` [K] lets a sink form stars only while gas below it lies within
  2 r_acc (0: always); `sink_star_mu` converts it to a sound speed and is also the
  cloud IC's mean molecular weight.
- `feedback_radius=0` is 3 dx. `wind_target_temp_K > 0` mass-loads winds to that
  temperature: 'conservative' sweeps up gas already there; 'torch' creates the extra
  mass as FLASH-Torch does; 'sink' takes it from the nearest sink.

### AMR and autodiff

- AMR refines the base grid by `amr_levels` factor-2 levels around steep gradients
  (`amr_criterion`; 'pressure' for blasts, 'vorticity' for shear, 'prho' for a
  collapsing cloud). `amr_regrid_interval=0` flags once at t=0; `amr_max_blocks`
  caps each level; `amr_block_bucket` rounds capacities up so a regrid rarely
  recompiles; the floors (0: off) reset a collapsing cell. `amr_dense_snapshots`
  writes the whole finest grid instead of the blocks (docs/AMR.md).
- `autodiff_mode` builds the same run and hands it to the task
  `scripts/examples/autodiff/<autodiff_task>.py`. `autodiff_fixed_dt=0` uses the CFL
  dt, under `stop_gradient` ('stopgrad') or differentiated through ('diff').
  'forward' mode is memory-flat in the step count; 'revolve' stores
  `autodiff_snapshots` states and recomputes the rest (docs/AUTODIFF.md).
